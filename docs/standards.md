# SkinNexus 协作开发规范与 Agent 开发指南

> 本规范对人类贡献者与 AI 编码代理同等生效。

## 1. 协作开发规范

### 分支与提交

- **分支模型**：trunk-based，`main` 保护分支 + 短生命周期 feature 分支（`feat/<scope>-<desc>`）；PR 合并前必须过 CI + 至少一人评审。
- **提交规范**：Conventional Commits（`feat|fix|docs|refactor|test|chore`），scope 用模块名（`auth` / `texture` / `ygg` / `plugin` / `migrate`）。

### 代码质量

- 格式化与 lint 强制（Go: golangci-lint；前端: eslint + prettier）；核心域单测覆盖率 ≥ 70%；CI 矩阵 = lint + test + build。

### PR 要求

- PR 模板含「动机 / 改动 / 测试 / 迁移影响」；
- 涉及 DB 的 PR 必须附迁移脚本；
- 涉及 Yggdrasil 协议的 PR 必须附兼容性验证记录（对照兼容基线清单）；
- 响应语义（204 / 错误体 / JSON 序列化）变更必须带 JSON 快照测试更新。

### 文档先行

- 协议/接口变更先改 `docs/` 再改代码；
- 架构决策记录（ADR）存 `docs/adr/`，编号递增；
- 对外契约以 OpenAPI schema 为接口事实源，变更同步更新。

### 安全

- 依赖锁定 + 定期审计；密钥、`.env`、私钥文件永不入库；
- 对外可见动作（发版、切库、协议变更）先示内容、经确认后执行。

## 2. Agent 开发指南（多 AI / 多代理协作）

### 仓库即上下文

- 根目录 `AGENTS.md`（等价 `CLAUDE.md`）描述架构地图、常用命令、禁区（不可逆迁移操作需人工确认）；
- 每个模块目录可有子级 `AGENTS.md`。

### 任务粒度与写范围

- 一个 agent 一个 PR 级任务；任务卡包含「动机、验收标准、涉及文件范围（write scope）、依赖任务」；
- 写范围不重叠，重叠需先协商；越界问题只记待办，不顺手改相邻问题。

### 证据铁律

- 结论标注出处（文件:行号 或命令输出）；
- 「不存在」类结论必须穷尽检索后才能下；
- 不确定项标注「待验证」，推断与事实分离陈述。

### 验证门

- 每步贴真实命令输出；失败即停、最多重试 1 次；
- 不编造输出、不以「应该可以」代替验证；
- 契约测试与 E2E 是合并门禁，不是可选项。

### 分工边界

- 重分析/重逆向任务走独立子代理并落盘分析文档；
- 实现代理不改他人 write scope 内文件；
- 重大选型决策走「多 AI 评析 → 分歧对齐 → 人工终裁」流程，评析提示词要求自包含（含事实基线、评分口径、输出格式）。

### 复盘沉淀

- 每完成一个里程碑，把踩坑与有效流程沉淀为技能/ADR，不重复交学费。
